## Pages and dynamic routing — 30 points
- A2-01 (12 points). At least four distinct page purposes are implemented with substantive portfolio content. Half credit: Two or three distinct pages have substantive content.

- A2-02 (12 points). A parameterized route shows different records for two values and handles an unknown value. Half credit: One valid value works but another value or the unknown-value case fails.

- A2-03 (6 points). Navigation reaches required pages and working links preserve the intended destination. Half credit: Most pages are reachable, with at least one broken required link.

## Contact behavior — 25 points
- A2-04 (5 points). Labeled name, email and message fields collect the intended values. Half credit: Fields exist but a label or value binding is incomplete.

- A2-05 (8 points). A valid submission reaches a server endpoint and returns success. Half credit: The endpoint or form works separately, but the complete submission fails.

- A2-06 (8 points). The server rejects blank name/message and malformed email with validation feedback. Half credit: Server validation rejects some required invalid cases but misses others.

- A2-07 (4 points). The interface clearly distinguishes successful submission from validation or request failure. Half credit: Feedback exists but a failure or success state is unclear.

## Code organization — 15 points
- A2-08 (8 points). Page, reusable UI, and server handling responsibilities are separated and easy to locate. Half credit: Responsibilities can be traced but substantial unrelated logic is mixed together.

- A2-09 (7 points). Names and structure make the page-to-form-to-endpoint flow readable without unexplained duplicate logic. Half credit: The flow is understandable but confusing names or duplicate logic obscure a material part.
